** TODO Optimize use of preprocessing step
   Currently 'X' is used in regexes to match 'any string that does not contain
   two newlines', this (intentionally) allows for whitespace at the beginning
   and end of the string. This is useful when the string is surrounded by
   markup characters (e.g. inside '[...]' etc.) less so when markup isn't
   surrounding the text (as with paragraphs, ATX headers `# ...`), or in a
   [bullet or ordered] list items, where there's no markup character to
   delineate the end).

   Would it be beneficial to be able to use 'Y' in the regexes to indicate a
   string that may not begin or end with a newline, but otherwise match the
   same as 'X'?

** TODO Support reference image inside inline links
   That is, this should work:

       [![alt][imgref]](url)

       [imgref]: imgurl

   Currently, the text is interpreted like this:

       [![alt][imgref]](url)
        ↑↑----alt-----↑↑url↑                       = image found
       [<img src="url" title="" alt="alt][imgref]">
       ↑----------text------------------↑↑imgref↑  = link found
       <a href="imgurl" title=""><img src="url" title="" alt="alt</a>">

   Another, slightly less insane than the current approach would be to escape
   all values outputted into HTML attributes, so that, at least, the above
   weird interpretation doesn't take place? This would cause the image to fail
   in a slightly saner way, at least.

** DONE Don't process markup in URLs
   CLOSED: [2025-01-19 Sun 18:38]
   This should be done my expanding all markup characters into '&#...;' so
   that, for example, `__...__` are not expanded into `<i>...</i>` inside URLs.

   However, we can't just invoke `e()` (a.k.a. `baremark.escape()`) since that
   will also escape `&` -- which the URLs may contain, since the backslash
   expansion is one of the first rules to be applied -- meaning that any
   previously expanded character will be expanded twice! (What was originally
   `\a` in an URL, got expanded into `&#97;` by the backslash expansion rule,
   would be turned into `&#38;#97;` by additional escaping.

   Maybe something like the following could be used?

   x.replace(/[*_~:"\\[\\]()]/g,m=>e(m))

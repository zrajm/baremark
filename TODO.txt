* TODO Policy decision -- Maintain or break Markdown compatibility?  :design:
  Break category:

  + Require blank lines around block tags, `+ BULLET`, `# HEADING`,
    `> BLOCKQUOTE`, dinkus `***`, ```CODEBLOCK`` etc---this would allow for
    multi-line `# heading`, and the block tags being more consistent in
    behavior (and thus easier to understand/use).

  + Don't allow lazy evaluation. All `> BLOCKQUOTE` would require leading `>`,
    and `- BULLET` continuation must be indented. This forces good-looking
    easier-to-read Markdown documents, but breaks CommonMark. It also means
    careless line breaking can cause a document to be interpreted differently.

  + Doubled `- BULLET` for sublists, and double '.' (or ')') for `1) NUMBERED`.

  Maintain:

  + Support indentation (indented code blocks, and indented sublists).

  + Allow full lazy evaluation.

** TODO Better handling of block elements (like `<div>`)                :bug:
   Will require:
   + Better paragraph tests for various HTML tags.
   + Some kinda decision on how to treat HTML tags.

   Currently, any `<div>` tags used must be placed on a separate lines, like
   this:
   ----------------------------------------
     <div>

     Paragraph 1.

     Paragraph 2.

     </div>
   ----------------------------------------
   If one instead do not separate the `<div>`s and write it like this:
   ----------------------------------------
     <div>
     Paragraph 1.

     Paragraph 2.
     </div>
   ----------------------------------------
   Baremark will naïvely wrap `<p>` tags around the paragraph that contains
   `</div>`, resulting in the following output:
   ----------------------------------------
     <div>
     Paragraph 1.

     <p>Paragraph 2.
     </div></p>
   ----------------------------------------
   Which will in turn will become even more messed up in the browser, because
   the browser (correctly thinking that a `</div>` cannot exist inside a `<p>`
   tag) will break up the `<p>` tag further.
   ----------------------------------------
     <div>
     Paragraph 1.

     <p>Paragraph 2.
     </p></div><p></p>
   ----------------------------------------
   It's not super clear how to actually handle this case. Should `<div>` tags
   be broken up and further parsed? How about other block tags (like
   `<table>`)? What does the CommonMark standard have to say about this?

   Should we append & prepend blank lines to all block tags while processing so
   that these are correctly handled by the paragraph processing?
